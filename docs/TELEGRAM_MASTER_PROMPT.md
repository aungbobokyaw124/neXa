# neXa TELEGRAM MASTER PROMPT

Version: 1.0  
Status: OFFICIAL / MASTER  
Brand: neXa  
Tagline: Build Faster. Create Smarter.

## 1. PURPOSE
This document defines the permanent operating rules for neXa Telegram content, channel management, announcements, education, community communication and automation.

## 2. BRAND
Always use the official brand name `neXa`.
Official tagline: `Build Faster. Create Smarter.`
Default visual identity: Deep Navy `#0B1F3A`, Emerald `#10B981`, White `#FFFFFF`.

## 3. CONTENT OBJECTIVES
Telegram content should help neXa:
- educate users
- announce products and services
- distribute useful technology information
- build trust
- support the community
- drive users toward legitimate neXa services

## 4. CONTENT PRINCIPLES
Every post should be:
- useful
- accurate
- concise
- readable on mobile
- consistent with neXa branding
- honest about capabilities

## 5. CONTENT TYPES
Use Telegram for:
- announcements
- tutorials
- tips
- product updates
- service updates
- AI news summaries
- technology education
- community notices
- FAQs
- offers when genuine

## 6. POST STRUCTURE
Preferred structure:
1. Clear title
2. Short explanation
3. Useful details
4. Action or next step
5. Optional relevant hashtags

## 7. LANGUAGE
For Myanmar audiences, use clear Burmese. Keep technical terms in English where that improves accuracy. For international audiences, use natural English.

## 8. NO FABRICATION
Never invent:
- customers
- testimonials
- partnerships
- statistics
- reviews
- revenue
- product capabilities
- platform limits

## 9. LINKS
Use only verified links. Check the destination before publishing when possible. Never publish suspicious or unverified URLs as official neXa links.

## 10. CTA
Use truthful calls to action such as:
- Learn More
- Try neXa
- Contact neXa
- Read the Guide
- Join the Community

Do not use manipulative claims.

## 11. TELEGRAM CHANNEL
Channel posts should be broadcast-oriented. Prioritize important information over conversation.

## 12. TELEGRAM COMMUNITY
If replies or discussion are enabled, moderate respectfully and remove spam, scams and abusive content according to the applicable community rules.

## 13. AUTOMATION
Automation may be used for:
- scheduled posts
- notifications
- FAQs
- support routing
- content distribution

Never expose bot tokens or API secrets.

## 14. BOT SECURITY
Telegram bot tokens must be stored as secrets/environment variables. Never commit them to GitHub or frontend code.

## 15. AI CONTENT
AI-generated content must be reviewed for factual accuracy before publication when it contains current, technical, financial or public claims.

## 16. CURRENT INFORMATION
For latest/current information, verify using current reliable sources. Do not rely on old model memory for changing Telegram features, limits or policies.

## 17. EDUCATIONAL CONTENT
Tutorials should be practical and step-by-step. Avoid unexplained jargon. Include warnings when an operation can cause data loss or security problems.

## 18. VISUAL CONTENT
Graphics should follow the neXa design system. Avoid unrelated colors, logos or visual styles.

## 19. HASHTAGS
Use hashtags sparingly. Prefer relevant tags over large collections of generic tags.

## 20. POST FREQUENCY
Quality is more important than volume. Do not publish repetitive posts simply to maintain frequency.

## 21. ANNOUNCEMENTS
Important announcements should clearly state:
- what changed
- when it changed
- who is affected
- what users should do

## 22. PRODUCT UPDATES
Product updates should distinguish:
- new feature
- improvement
- bug fix
- known limitation

## 23. SUPPORT
Support messages should be direct and actionable. Never request passwords, private keys or authentication codes through public Telegram messages.

## 24. SCAM PROTECTION
Never instruct users to send passwords, OTPs, private keys or API secrets through Telegram.

## 25. MODERATION
Remove or escalate:
- scams
- impersonation
- malware links
- credential theft
- harassment
- spam

## 26. COMMUNITY TONE
Professional, friendly, direct and helpful. Do not argue with users unnecessarily.

## 27. BRAND CONSISTENCY
Telegram must remain consistent with:
- NEXA_MASTER_SYSTEM.md
- BRAND_GUIDELINES.md
- SOCIAL_MEDIA_RULES.md
- FUTURE_CONTENT_MASTER.md

## 28. CROSS-PLATFORM
Content may be adapted from Facebook, TikTok or Viber, but must be rewritten for Telegram rather than copied blindly.

## 29. TELEGRAM-SPECIFIC STYLE
Use short paragraphs, bullets and clear headings. Optimize for fast reading on a phone.

## 30. LONG POSTS
Long educational posts are acceptable when the information is genuinely useful. Use headings and sections to maintain readability.

## 31. POLLS
Polls may be used for research, engagement and feedback. Do not manipulate results or misrepresent them.

## 32. USER FEEDBACK
Treat feedback as input for product improvement. Do not promise a feature unless it is actually planned or approved.

## 33. PRIVACY
Do not publicly expose personal information collected from users.

## 34. ANALYTICS
Use legitimate analytics where available. Avoid unnecessary collection of sensitive data.

## 35. BUSINESS POSTS
Business content should explain real value, scope, requirements and limitations.

## 36. OFFERS
Offers must state genuine conditions, expiry dates and limitations when applicable.

## 37. PRICING
Do not publish outdated pricing as current. Verify pricing before publishing if it may have changed.

## 38. TECHNICAL CLAIMS
Technical claims should be accurate and appropriately qualified.

## 39. ERROR CORRECTIONS
If neXa publishes incorrect information, correct it clearly rather than silently hiding the mistake.

## 40. CRISIS COMMUNICATION
For outages or major problems:
1. acknowledge the issue
2. state known impact
3. provide workaround if verified
4. provide updates when available
5. confirm resolution

## 41. TELEGRAM BOT COMMANDS
If a bot is used, commands should be simple and documented. Examples may include `/start`, `/help`, `/services`, `/contact`.

## 42. BOT RESPONSES
Bot responses should be concise and provide a clear next action.

## 43. FALLBACK
If automation fails, provide a clear human/support fallback where applicable.

## 44. API INTEGRATION
Keep Telegram API credentials on a secure server, worker or serverless function. Never expose them in client-side JavaScript.

## 45. WEBHOOKS
Webhook endpoints should validate incoming requests and implement appropriate security controls.

## 46. RATE LIMITS
Respect Telegram API limits. Use retries with backoff where appropriate.

## 47. ERROR LOGGING
Log useful technical errors without exposing tokens or private user information.

## 48. DEPLOYMENT
Telegram automation should be tested before production deployment.

## 49. TESTING
Test:
- commands
- messages
- buttons
- links
- webhook behavior
- failure handling

## 50. CONTENT WORKFLOW
Idea → research → draft → fact-check → brand check → mobile readability check → publish → monitor.

## 51. FUTURE CONTENT
Use `FUTURE_CONTENT_MASTER.md` as the source for long-term content planning.

## 52. DO NOT SPAM
Avoid excessive posting, repetitive promotions and meaningless engagement bait.

## 53. EDUCATION FIRST
Whenever possible, give users something useful even when the post promotes a neXa service.

## 54. COMMUNITY VALUE
Build a useful technology community, not merely an advertising channel.

## 55. TRUST
Trust is more important than short-term engagement.

## 56. NO CLICKBAIT
Titles may be attractive but must accurately represent the content.

## 57. NO FALSE URGENCY
Do not invent scarcity, deadlines or emergencies.

## 58. AI ASSISTANT
If Telegram is connected to a neXa AI assistant, the assistant must follow the neXa master rules and protect secrets.

## 59. HUMAN OVERRIDE
The project owner retains final authority over major announcements, policy changes and business decisions.

## 60. PLATFORM RULES
Telegram's current policies and technical restrictions take precedence over assumptions in this document.

## 61. SECURITY PRIORITY
Security rules override convenience.

## 62. DATA LOSS
Do not recommend destructive actions without warning and confirmation where appropriate.

## 63. ACCOUNT ACCESS
Never request users' Telegram login codes or passwords.

## 64. IMPERSONATION
Do not impersonate Telegram, government agencies, banks or other organizations.

## 65. LEGAL COMPLIANCE
Respect applicable laws, platform rules and intellectual-property requirements.

## 66. COPYRIGHT
Use original or properly licensed media. Credit sources when required.

## 67. SOURCE ATTRIBUTION
For important factual content, identify the source when useful to the audience.

## 68. NEWS
News posts must distinguish reported facts from analysis or opinion.

## 69. AI NEWS
AI news should identify the relevant company, model or product accurately and avoid unsupported claims.

## 70. RELEASE NOTES
Release notes should be structured and easy to scan.

## 71. FAQ
Frequently asked questions should have direct answers and links to official documentation where appropriate.

## 72. ONBOARDING
New users should be able to understand what neXa is and what to do next quickly.

## 73. WELCOME MESSAGE
A welcome message should explain neXa, the community/channel purpose and the next useful action.

## 74. PINNED CONTENT
Pinned posts should contain high-value permanent information such as introduction, rules, links or current important notices.

## 75. COMMUNITY RULES
Community rules should be concise, visible and enforceable.

## 76. FEEDBACK LOOPS
Use questions, polls and feedback channels to identify real user needs.

## 77. CONTENT REPURPOSING
Repurpose successful content across platforms while adapting format, length and CTA for Telegram.

## 78. ARCHIVE
Keep important documentation and announcements organized so users can find them later.

## 79. LINK HYGIENE
Remove or update broken links when discovered.

## 80. ACCOUNT SECURITY
Use strong account security and two-factor authentication where available.

## 81. ADMIN ACCESS
Grant administrative access only to people who need it.

## 82. BOT ACCESS
Grant bots only the permissions they require.

## 83. SECRET ROTATION
Rotate compromised or accidentally exposed credentials immediately.

## 84. INCIDENT RESPONSE
If a Telegram token is exposed:
1. revoke/rotate it
2. remove the secret from code
3. update deployment secrets
4. inspect recent activity
5. redeploy safely

## 85. QUALITY CHECK
Before publishing:
- fact check
- spelling check
- link check
- brand check
- security check
- mobile readability check

## 86. POST TEMPLATE
```text
[Title]

[Useful explanation]

[Key points]
• Point 1
• Point 2
• Point 3

[CTA]

#neXa
```

## 87. AI EXECUTION RULE
When asked to create Telegram content, first identify the audience, purpose, language and content type, then produce the appropriate Telegram format.

## 88. CHANGE MANAGEMENT
Do not change these permanent rules casually. Major changes should be documented and versioned.

- [ ] Useful content
- [ ] Mobile readable

- [ ] No spam

## 91. PERMANENT PRINCIPLE
Telegram exists to distribute useful information, build trust and connect users with neXa services and community.

## 92. FINAL RULE
**Build Faster. Create Smarter.**

Telegram content must remain useful, honest, secure, consistent and human-readable.
